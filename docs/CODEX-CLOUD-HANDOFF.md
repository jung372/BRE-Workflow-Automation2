# Codex 클라우드 개발 인수인계

## 현재 코드와 범위

이 브랜치는 풍력대동여지도 검토 목록, 비공개 추적 내보내기, 이력 기한·지역 집계, 사업지 주소 및 발행 검증 관련 코드와 합성 테스트를 포함한다. 전체 허가대장 검토와 검산은 아직 완료되지 않았다. 검토 결과나 운영 상태를 이 문서의 코드 작업 완료와 혼동하지 않는다.

사용자 우선순위는 육상풍력 사업의 개별 추적이다. 정보가 빠지거나 상충해도 관측을 보존하고, 확인되지 않은 유형·사업 동일성·반복 번호는 추정해 승인하지 않는다. 환경영향평가는 신청·접수 및 협의 완료 여부 위주로 확인하고, 개발행위허가와 사용전검사를 우선 조사한다. 해상풍력은 조사 대상에서 제외한다.

## 안전한 개발 환경

Codex 클라우드에서 이 저장소의 인수인계 브랜치를 선택한 후 저장소 루트에서 실행한다.

```bash
bash scripts/codex_cloud_setup.sh
source .venv-cloud/bin/activate
python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/test_wind_news_frontend.js tests/test_solar_news_frontend.js tests/test_wind_map_frontend.js
```

Python 3.11 이상과 Node.js가 필요하다. 설치는 기존 requirements 파일을 사용하며 서비스 시작, 데이터 수집, 원격 전송 또는 배포는 수행하지 않는다. PDF 이미지 대조가 필요한 환경에는 별도의 렌더러가 필요하다.

운영 DB·원본·검토 배치·백업은 Git 저장소 밖의 비공개 런타임에 있다. 클라우드 체크아웃에는 자동으로 포함되지 않으므로 저장소만으로 실제 원문 검토를 재개할 수 없다. 사용자가 승인한 안전한 경로로 필요한 자료와 일관 백업을 제공받기 전에는 합성 fixture로 코드만 검증한다. 비공개 자료, 계정 정보, DB, 검토 기록을 공개 저장소나 테스트 fixture에 넣지 않는다.

실자료를 사용할 수 있게 되면 먼저 공통·프로젝트 지침과 `wind_map/README.md`의 원본·검토·백업 절차를 읽고, 실제 런타임의 진행상태·작업 중인 묶음·원본 해시와 백업을 확인한다. 비공개 DB를 임의로 초기화하거나 테스트로 덮어쓰지 않는다. 페이지 승인, 행 분류, 법적 연결과 발행 차단은 각각 근거를 갖춰 검증한다.

## 운영 경계

이 저장소의 `main` 및 `feature/**` 푸시는 서버 배포 워크플로를 시작할 수 있다. 코드 리뷰는 `codex/` 브랜치에서 진행하고, 운영 반영은 별도 승인 범위를 확인한다. 원격 push, 웹 데이터 발행, Teams 전송, 정보공개청구 제출은 각각 사용자가 승인한 범위에서만 수행한다. `run_local.py --no-push`도 로컬 쓰기와 수집을 수행하므로 읽기 전용 검사로 취급하지 않는다.

클라우드에서 이어갈 작업 예시:

> `docs/CODEX-CLOUD-HANDOFF.md`, `AGENTS.md`, `PROJECT_GUIDE.md`, `wind_map/README.md`를 먼저 읽고, 비공개 운영 데이터의 가용 여부를 확인한 뒤 합성 테스트로 코드의 현재 상태를 검증해 주세요. 실제 자료가 없으면 이를 명시하고, 육상풍력 추적·허가 연결을 개선할 수 있는 코드와 테스트를 작업해 주세요. 검증 게이트를 완화하거나 운영 데이터를 공개하지 마세요.
